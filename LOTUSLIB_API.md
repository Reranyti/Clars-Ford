# LotusLib API (обновлено под v1.1010)

> **⚠ Скоро проект полностью изменится (теперь он называется Clars Ford, ранее Lotus Blight). Документ описывает старую версию и скоро устареет. / The project (now Clars Ford, formerly Lotus Blight) is about to change completely; this document describes the old version.**


LotusLib — отдельный библиотечный JAR для расширений Clars Ford и совместимости с крупными
сборками Forge 1.20.1.

## Артефакты — версии обновлены

Мод перешёл с `major.minor.patch` на плоский формат `1.NNNN` (с v1.1010). Оба jar-а теперь всегда
имеют одинаковый номер версии, собираются одним и тем же `mod_version` из `gradle.properties`:

| Файл | Назначение |
|---|---|
| `lotuslib-1.1010.jar` | Общие классы очередей, интеграций, спецификаций версий и API расширений |
| `lotusblight-1.1010.jar` | Основной контент: заражение, ветки диалога, StarFall, Побег, босс-файл, Хончо, метеоритный тир, карантинная граница |

Оба JAR по-прежнему должны находиться в папке `mods` вместе — Clars Ford использует классы из
LotusLib.

## Необязательные интеграции — подтверждено, список расширен

`LotusIntegrationManager`/`LotusIntegrationSpec` работают как описано изначально. Реально
подключённые опциональные интеграции на текущий момент: Streams Reflowing, TerraBlender, YACL,
JourneyMap, Chat Overhaul. Единственная **обязательная** внешняя зависимость — Ex Meteor Shower
(для комет StarFall), GeckoLib и Curios рассматривались отдельно (см. `IDEAS_AND_MODS.md`).

## Производительность

`LotusTaskQueue` по-прежнему ограничивает тяжёлые задачи за тик. Активная учебная зона первого
игрока — 32 чанка (максимум допустимого в конфиге `activeChunkRadius`, дальше по конфигу
подниматься некуда). С v1.91.0 это уже не жёсткий стоп: очаги вне этой зоны всё ещё тикают, просто
с плавно затухающей скоростью вместо полной остановки.

## Правила совместимости — не менялись

Интеграции не заменяют блоки/биомы других модов без проверки. Контент — в собственном namespace
`lotusblight`. Единственное дополнение: за время разработки минимум 4 раза находился один и тот же
класс бага — синхронный вызов `setBlock`/`getBlockState` на потенциально незагруженной позиции без
`hasChunkAt`, приводящий к дедлоку серверного тика. Любая новая интеграция или система, работающая
с произвольными позициями мира, должна проверяться на этот паттерн в первую очередь.
